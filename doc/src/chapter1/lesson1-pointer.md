## 2.1 问：指针和引用区别



回答：

### 只能使用指针、不能使用引用的场景

#### 1. 需要频繁修改、删除 重要的数据结构
    
- 比如链表、树等底层数据结构的实现。
- 这类结构的节点需要灵活地“重新指向”或“断开连接”，只能用指针，引用无法重新绑定。
-  来源：无论课本上 提到数据结构 还是项目使用容器还是自定义基础库 经常用到。无论 c 还是 c++，java ，go ，rust 都数据结构，都涉及数据结构。

#### 2. 需要延迟初始化的类成员变量
- 构造函数中无法立即确定某成员的具体对象时，只能保存一个指针，等到运行时再指向目标。（构造函数考点，是否声明为虚函数，构造函数里面可能有虚函数吗）
- 例如 与数据库链接，线程池，还有缓存等重要资源
- 来源:无论开源项目还是公司 重要组件都是这样设计的。

### 3. 与 C 接口交互时  
- 在C语言中，没有引用传递（pass by reference）的概念，只有值传递。
- 这是c 语言特点决定的 接近硬件，必须使用指针，减少中间转换。

#### 4. 资源所有权

- 引用是变量的**别名**，不负责资源所有权。语法上 `delete` 引用会直接报错。  
- 而指针代表“我可能持有、释放资源”，有所有权管理责任，依靠开发者经验

| 语言       | 内存管理            | 安全机制      | 性能  |
| -------- | --------------- | --------- | --- |
| **Rust** | 编译期所有权          | 强安全（静态检查） | 极高  |
| **Go**   | GC（运行时）         | 弱安全（动态）   | 较高  |
| **C++**  | 手动 + 智能指针（RAII） | 依赖程序员     | 极高  |

## 2.2 问：指针和数组区别

### 数组连续内存
- 编译时候大小固定
-  连续内存，减少内存碎片
- 缓存有好，只需一次访问数据，访问指针 和指针指向数据 可能2 次访问


举例：Redis 核心数据结构数组使用及编码转换

| 数据结构     | 小型编码（数组/压缩形式）                 | 大型编码（指针/动态结构）           |
| -------- | ----------------------------- | ----------------------- |
| **list** | **ziplist**（连续内存数组）           | **linkedlist**（双向链表）    |
| **set**  | **intset**（整数数组）              | **dict**（哈希表，指针数组 + 链表） |
| **zset** | **ziplist**（压缩数组存储元素 + score） | **skiplist + dict**     |
| **hash** | **ziplist**（连续数组存 key/value）  | **dict**（哈希表）           |
| sds      | 柔性数组允许 **动态、连续、高性能字符串存储**     |                         |
|          |                               |                         |
- 柔性数组 **编译时候 大小是不固** 但是 初始化分配连续内存

```c++
struct sdshdr {
    int len;      // 当前字符串长度
    int free;     // buf 中剩余可用空间
    char buf[];   // 柔性数组，实际存储字符串 + '\0'
};

len：已经存储的字符串长度
free：缓冲区剩余未使用空间，用于扩展
buf[]：柔性数组，紧跟在结构体后面连续分配 sizeof buf[]=0


```

假设我们要创建一个长度为 `initlen` 的 sds：

```c
size_t total_size = sizeof(struct sdshdr) + initlen + 1; // +1 为 '\0' sdshdr 

sdshdr *sh = (sdshdr*)malloc(total_size);

```
**说明：**

1. sizeof(struct sdshdr) → 包含 len 和 free 两个整数（通常 8 字节）
2. initlen + 1 → 分配 buf[] 的实际空间（字符串 + 末尾 \0`）
3. `buf` 实际存储在结构体紧邻内存后 → 连续内存


- **连续数组 / 柔性数组**
    - 高 CPU cache 命中
    - 遍历连续元素一次预取
- **指针 **
    - 插入删除灵活
    - 遍历可能跨内存 → cache miss 较高
- **Redis 平衡策略**
    - 小型数据 → 紧凑数组/压缩编码
    - 大型数据 → 指针动态结构


## 2.3 问:new 和 malloc 的区别


提示：

- 回答new 和 malloc 区别 考虑 c  和 c++区别 例如 c 语言不提供引用这个抽象

#### 区别 1： 系统分层设计 

- malloc（） 是 c 语言标准库（Linux操作系统下所说的libc即glibc）库函数，是一个函数
- new 是 c++ 关键字，new 不是函数，不支持重载,  new 实现必然依赖底层 libc++（libc++是针对clang编译器特别重写的C++标准库）/libstdc++（gcc）**库实现  
- operator new（） 是c++ libstdc++ 标准库函数，静态函数，静态函数自然是不能是虚函数，默认实现通常调用 C 标准库的 `malloc`
- 关键字：new 是一个抽象，隐藏具体实现，更加灵活【如何灵活，隐藏什么】


![https://godbolt.org/](https://s2.loli.net/2025/10/12/WEBQyLZ7Uwuk1av.png)



Foo* ptr = new Foo() 完整过程

在 C++ 中，`new` 运算符实际上可以拆成三步：

1️⃣ **计算对象大小**

- 编译器根据类型 `Foo` 的大小（`sizeof(Foo)`）和对齐要求计算需要分配的内存大小。
    
2️⃣ **分配内存**【可定制】

- 默认情况下调用的是全局 `operator new(size_t)
- **可以自定义**：类可以重载 `operator new(size_t)`，或者用 placement new 指定自定义内存位置。
    
3️⃣ **调用构造函数**

- 内存分配成功后，C++ 会在该内存上调用 `Foo::Foo()` 构造函数完成对象初始化。
    

```c
Foo* ptr = new Foo();
		│
		▼
   计算对象大小 
        │
		▼
	分配内存
		│
		▼
 方式 1：查找类内operator new --用户自定义
│
├─存在 → 调用类内 new

└└─不存在 → 调用全局 ::operator new ---用户自定义
 
	│
	▼
内存分配（malloc）
	│
	▼
调用 Foo 构造函数
	│
	▼
返回对象指针

```

#### 区别 2：new 可以高度定制

new 需要 三个过程 1 计算大小  2 分配内存  3 调用 构造函数 

步骤 1 和 3 保持不变，步骤 2 可定制（为什么明天分享）



``` c++

char buffer[sizeof(Foo)];

Foo* p = new(buffer) Foo(); // placement new


不分配内存

内存已经由用户提供（buffer），所以不会调用 malloc/mmap
    
步骤 2 被用户完全控制

```


| 特性   | 普通 new                   | Placement new     |
| ---- | ------------------------ | ----------------- |
| 内存分配 | 调用 operator new / malloc | 用户提供地址，不分配        |
| 调用构造 | ✔                        | ✔                 |
| 调用析构 | `delete` 会调用析构           | 需手动调用 `p->~Foo()` |
| 系统调用 | 可能（malloc/mmap）          | 不需要               |
| 用户态  | ✔                        | ✔                 |



- 注意事项，一旦使用 Placement new
- 不能使用 默认 delete 方式，自动调用 会调用析构，释放空间，这个空间希望循环利用不释放。
#### 为一个类自定义 new 和 delete 

|维度|① 类内 new/delete|② 全局 new/delete（弱符号）|③ LD_PRELOAD + tcmalloc|
|---|---|---|---|
|生效时机|**编译期**<br><br>（静态绑定）|**链接期**<br><br>（符号强弱覆盖）|**运行期**<br><br>（动态装载器优先级）|
|作用范围|仅该类/基类查找链|全局（除已绑定到类内的 new）|全局（动态库与主程序）|
|机制|作用域查找 + 非虚（无 vtable）|弱符号 vs 强符号|预加载库先解析同名符号|
|是否依赖弱符号|否|是（libstdc++ 默认全局 new 为 weak）|否（依赖 ld.so 解析顺序）|
|源码是否需改动|需要（在类内写函数）|需要（提供全局 operator new/delete）|不需要（设置环境变量即可）|

## 三、总结

✅ 指针与引用的区别 ？

指针：
- 从对数据结构查找，删除基本操作出发 主要区别就是 指针灵活 不绑定
- 从所有权考虑 

引用： 
- 从语法参数传递 值传递，无引用
- 引用 增加复杂性，万能模版 可能无法区别 这变量是什么类型的，需要std::move() 等转换

✅ 指针与数组的区别

- 从减少内存碎片和 cpu 缓存考虑
- 对比 Redis 对象根据数据量大小 采用具体编码方式 数组 还是链表

✅ new和 malloc 的区别

- 不同层次划分
- new 高度定制，建立更好层次

✅ 为一个类自定义 new 和 delete 【可选】
